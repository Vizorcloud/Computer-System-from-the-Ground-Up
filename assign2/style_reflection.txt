1. We are extra conscientious with error handling in gpio_set_function because the function cannot return a value, unlike functions such as gpio_get_function where the caller can check the result. In gpio_set_function, there is only one valid action for a given input, so it is the responsibility of the developer of the low-level function to ensure that invalid inputs are safely handled.

2. In my clock.c file I use three global variables within the local file and I would not change that. This is becaues these variables are all constants in regards to the bit patterns of digits and the mapping of the peripheral components to the Mango Pi. A majority of my functions and helpers draw upon these constants to operate correctly and by not keeping them as globals I would have to repeatedly define them in every place I use them which would be unnessacerily tedious.
